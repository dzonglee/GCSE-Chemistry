# GCSE Chemistry project instructions

Read docs/build-plan.md and docs/validation.md before extending the app. Keep content and marking separate from UI. Use the existing checkout; no worktree is needed unless the user requests one.

The user requires lesson-by-lesson development: read actual teaching and exam materials, consider the specific concept and interactions, author and review that single lesson, then send sample screenshots before moving to further lessons. Do not bulk generate or release unreviewed lesson banks. All 95 routes now have individually researched journeys and explicitly delivered screenshots. See docs/rebuild-status.md and the individual lesson reviews for the current evidence. Final statement-level qualification/tier mapping, cumulative assessment breadth, shared input/UX audit and complete frozen regression remain open. AQA specifications and selected paired exam questions/mark schemes have been read; Pearson comparison is limited and full OCR alignment is unverified.

The product takes its design and learning principles from the neighbouring GCSE-Maths repository: white cards on cool grey, blue actions, topic colours, local Archivo headings and Atkinson body font, visible curriculum navigation, and task-first interactive learning. A navigation widget alone is not a learning model. Every learning feature must provide a meaningful chemical manipulation, prediction or answer with explanatory feedback; preserve keyboard/touch access and text interpretations of diagrams.

Practice, independent checks, mixed retrieval and delayed review must remain distinct. Exposure is global across sessions. Repeated, hinted or model-assisted answers must never become fresh independent evidence. No mastery or grade prediction from completion. Keep assessment answers hidden until whole-set submission. Retain check history, drafts and exposure when restarting.

Saved learning uses only gcse-chemistry.progress.v1. Preserve unreadable raw records and prevent stale cross-tab overwrites. Warn about storage failures but allow study. Deleting data must be explicit and scoped; do not clear unrelated storage.

Board preference records context, not certified alignment. Current lesson tags are indicative. Do not claim full specification coverage or official exam equivalence. Practice papers include original short sets and four individually reviewed cumulative samples: Foundation/Higher Paper1 and Paper2. Further cumulative sets require individual review and explicit screenshot delivery before work proceeds. Practical work is simulated/data interpretation; no instructions for unsupervised chemical experiments. No paid APIs, generated videos, tracking, deployment, accounts or messaging are required by this implementation.

Node >=22; npm ci with npm_config_cache=/workspace/.npm-cache. Development runs on 3001 and production browser tests on 3201. Tests use /usr/bin/chromium or CHROMIUM_PATH. Do not run dev and build simultaneously. Read the relevant installed Next.js guide in node_modules/next/dist/docs before changing framework conventions.

Required checks: npm run typecheck; npm run lint; npm run test:unit; npm run build; npm run test:e2e. Unit config explicitly excludes browser specs. Browser screenshots and traces belong in ignored test-results, not tracked source. Check correct, incorrect, reset, reload, blocked/corrupt storage and cross-tab paths, desktop/mobile layout and automated accessibility. Preserve original font licences.
